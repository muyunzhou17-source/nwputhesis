\chapter{面向低时延和低功耗的WLAN仿真平台设计与实现}
\chaptermark{面向低时延和低功耗的WLAN仿真平台设计与实现}
随着区域内通信设备数量，无线网络流量种类和规模的持续增长，未来网络对通信低时延、
能量低功耗要求尤为迫切。然而，任何预研技术在迈向落地前都需要进行前期的仿真和验证，
以评估其在实际网络环境中的性能表现，为后续的工程落地提供实验依据，可有效缩短开发流程。
因此，一个优秀且可靠的仿真平台对于网络性能评估和优化具有重要意义。本章在课题组现有的
链路级WLAN仿真平台的基础上，针对下一代WLAN的最新需求，设计和实现了低功耗粒子化接入技术、
增强型EDCA接入技术和其对应的强化学习改进模块仿真，实现了具备低时延和低功耗保障能力的
下一代WLAN仿真平台。本章首先介绍仿真平台的整体架构和设计思路，然后详细阐述低时延和低功耗
保障功能的设计与实现，最后通过仿真验证展示平台的性能表现，结果表明该仿真平台能够有效
支持下一代WLAN的低时延和低功耗需求，并且能够为后续的第四，第五章的研究提供可靠的实验基础。

    \includegraphics[width=1.0\textwidth]{第三章仿真平台架构.pdf}
    \caption{仿真平台整体架构}

网络仿真是评估协议与系统行为的重要手段。目前主流的网络仿真平台有很多： NS-2
（Network Simulator 2）、NS-3（Network Simulator 3）、OMNeT++（Objective Modular
 Network Testbed in C++）等。其中，NS-3 是开源免费的离散事件网络仿真器，具有完善的
 节点、网卡、信道与协议栈抽象，提供丰富的开源模块和可观测接口，并支持 C++ 与 Python
 编程，便于在统一场景下开展可重复的对照实验。课题组前期已基于NS-3 搭建了链路级 WLAN
 仿真平台，但该平台尚未覆盖面向下一代WLAN的低时延、低功耗接入机制。为此，本章在原有
 平台基础上进一步实现了IEEE802.11bn协议中各层的功能，支持低功耗粒子化接入、
 P-EDCA 及其强化学习优化算法。如\autoref{3-1}所示，图中标注的子模块为本文设计并实现
 的部分，各层已有的基础功能沿用课题组前期工作。下面分别对平台的主要组成部分进行介绍。

（1）离散事件仿真内核

本仿真平台基于 NS-3 的离散事件仿真内核运行。离散事件仿真将连续时间离散为一系列不
连续的时间节点，仿真时间只在事件发生时向前跳跃，事件之间的空闲时段被忽略。平台中
的产包、收发包以及各类协议处理函数均被抽象为离散事件，由离散事件调度器按照事件时
间戳插入事件队列并依次调度执行。调度器向各协议模块提供事件插入、删除和查询接口；
随着事件不断执行，仿真时间逐步推进，直至预设的仿真结束时间。基于该内核，平台能够
在保证仿真精度的同时降低大规模网络场景下的计算开销。

（2）应用层与传输层

应用层负责业务模型的建模与数据包生成。每个通信节点可配置独立的应用层，根据业务模
型持续产生数据包并下发至传输层；业务模型的主要参数包括数据包大小和数据包产生间隔。
应用层在产包时记录数据包大小与产生时间，为后续吞吐量、时延与能耗统计提供依据。对
于粒子化接入流程，平台在应用层与传输层之间设置了粒子化特性添加模块，为业务数据添
加粒子化属性，使 MAC 层能够根据业务特征进行差异化的接入与准入判决。传输层完成数
据包的封装与端到端交付，并将数据下发至 MAC 层。

（3）网络设备与信道

网络设备是连接上层业务与无线信道的核心部分，由 MAC 层和 PHY 层组成。MAC 层负责信
道接入与不同业务流的接入控制，PHY 层负责数据帧的收发与解析，并通过能量管理模块和
功率控制模块为低功耗机制提供支撑；其下的信道对路径损耗与衰落特性
进行建模，为仿真提供信道状态信息。

（4）粒子化接入模块

粒子化接入模块由信道接入、DUO 交互模块和粒子化准入模块依次构成。信道接入模块完成
载波侦听、退避与信道竞争；DUO 交互模块实现 Wi-Fi 8 中的动态不可用机制
（Dynamic Unavailability Operation，DUO）。DUO 原本是 Wi-Fi 8 引入的节能机制，本
文利用其动态不可用窗口的通告能力来降低时延。该模块负责节点间关于链路可用性状态的
信息交互，使对端在节点不可用窗口内避免调度传输；粒子化准入模块结合业务数据携带的
粒子化属性、当前信道状态以及 DUO 交互得到的可用性信息，判断是否允许该业务接入信
道，从而减少无效接入带来的能量开销。

（5）P-EDCA 模块

P-EDCA 模块在传统 EDCA 的基础上引入 P-EDCA 条件判断：信道接入完成后，由条件判断
模块根据业务类型与当前信道状态决定采用 RTS/CTS 交互还是 P-EDCA 流程，随后由
P-EDCA 模块执行接入决策与参数配置，实现不同优先级业务的差异化信道竞争，为低时延
业务提供更快的接入机会。

（6）P-EDCA 强化学习模块

为提升 P-EDCA 在动态网络环境下的自适应能力，平台设计了 P-EDCA 强化学习模块，与
MAC 层的 P-EDCA 模块构成闭环优化。该模块首先从仿真日志中获取网络状态数据并记录当
前状态 S；DQN 智能体根据状态 S 进行决策，输出动作并调整 P-EDCA 策略。在每个统计
窗口结束时，模块统计窗口内的状态与奖励，存入经验回放池，用于 DQN 网络的训练。
通过“仿真—决策—反馈”的迭代，P-EDCA 策略能够逐步适应不同的业务负载与信道条件。

综上所述，平台的应用层、传输层与 MAC 层主要完成系统级仿真，重点关注接入控制、资
源分配与调度策略对吞吐量、时延、丢包率及能耗等指标的影响；PHY 层与信道模块侧重于
链路级仿真，主要完成信号收发、能量与功率管理、信道衰落与干扰建模等功能。基于上述
架构，平台能够实现系统级与链路级一体化仿真，而粒子化接入、P-EDCA 及其强化学习模块
，可以使平台可以通过分析和预测数据包和网络参数，实现时延和功耗的Qos保障。

\section{仿真平台设计}
本节在 3.1 节仿真平台架构的基础上，将详细介绍仿真平台各功能模块的设计。围绕下一代
WLAN 的低时延与低功耗需求，仿真平台主要分为三部分：WLAN网络仿真整体设计，低时延保
障功能设计以及低功耗功能设计。其中低时延保障功能设计由粒子化接入模块、P-EDCA模块和
其强化学习改进模块组成；低功耗功能设计由 DUO 机制模块和粒子化准入模块配合实现。

\subsection{整体设计}
仿真平台的整体设计主要包括仿真平台的功能模块划分、数据包传输路径以及各模块之间的交互关系。
平台采用模块化设计思想，将不同功能模块进行解耦，便于后续的扩展和维护。整体设计中，应用
层负责业务模型的生成和数据包的产生，传输层负责数据包的封装和传输并将其透传给MAC层；
MAC层负责信道接入和资源调度，同时也是协议栈的主要实现位置，处理完数据包后下发给PHY层；
PHY层发送时主要作用为将数据包传递给信道，接收时数据包时还具备能量管理和功率控制功能，将符合
接收条件的数据包传递给MAC层；信道主要负责对信号的衰落和干扰进行建模，实现不同节点之间的通信。
各模块之间通过接口进行数据交换，实现数据包的传递和处理。主要架构如下图所示。

代码设计上，仿真平台运用C++面向对象的编程思想，将不同的节点，应用层、MAC层、PHY层和信道
抽象为类，通过继承和多态实现不同层间的交互。

（1）节点：节点对应 Node 类，它自身不处理具体协议，主要负责把各层对象组合在一起：
应用层、协议栈（传输层和网络层）、网络设备（MAC层 和 PHY层）。

（2）应用层，MAC层和PHY层：每个通信节点可配置独立的应用层、MAC层和PHY层，
各层对象之间通过固定的接口函数传递数据包,通过多态从Regular基类接口将数据包下发到
对应的wifi11bn接口。其中，向下传递数据包调用 SendDownFromHigh()和SendDown()，
向上传递数据包调用 SendUpFromLower()和SendUp()。应用层，MAC层和PHY层继承于相同的基类，
保留了相同规范的接口函数，便于后续的扩展和维护。

（3）信道：ChannelBase类模拟信道，信道是全局共享对象，维护所有通信节点PHY层的指针；
某个节点发送数据包时，信道会遍历其他节点的PHY层，根据节点间距离计算传播时延和路径损耗，
按传播时延将数据包转发给对应PHY层。
\subsection{低时延保障功能设计}
本节将介绍仿真平台中低时延保障功能各模块的设计思路，包括粒子化接入模块设计，
P-EDCA模块功能设计，以及P-EDCA结合DQN强化学习联合优化设计。
\subsubsection{粒子化接入模块设计}
粒子化接入模块流程的设计如图\autoref{3-3}所示，下面将详细粒子化接入模块的基本
设计架构以及与Wi-Fi基本功能模块之间的关系。粒子化接入模块主要有三部分内容组成：

（1）数据包的粒子化：应用层产生数据包时，给每个数据包的公共包头添加粒子化指标
deadline时延容忍，产生时刻与截止时间等信息，将 STA 业务流粒子化建模为信息粒子群，
每个信息粒子对应一个待发送数据包，方便后续模块使用。

（2）粒子化准入模块：粒子化准入模块在数据包进入发送队列前进行准入判决，按照deadline
顺序遍历队列中的所有数据包，剔除超时数据包后，逐步计算本次传输所需的最小可达带宽（最
小传输速率），计算过程中若出现准入数据包后计算的最小可达带宽大于当前信道可用带宽，则
剔除该数据包，直至队列中所有数据包遍历完成或达到AMPDU上限。剩余粒子构成有效信息粒子群，
交由多目的地址聚合发包流程使用。

（3）多目的地址聚合发包：从有效粒子群中根据deadline顺序组包，控制帧交互阶段发送MU-RTS帧
通知STA接收端准备接收，并采用EDF策略进行传输，后续目的地址后拆包根据MPDU目的地
址判断是否为自己的数据包，并统一回复ACK，完成发包流程。


（4）数据包超时处理：接收端 PHY 层收到数据包后，若数据包中的截止时间字段早于当前
时刻，则判定该数据包已超时并将其丢弃；该数据包不会在接收端后续回复的 ACK 确认
信息中被确认，统计模块将其计为丢包。
